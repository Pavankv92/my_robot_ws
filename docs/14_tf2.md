# TF2

TF keeps track of where every coordinate frame is (robot base, wheels, sensors, map) relative to the others, over time.

## Topics

| Topic | Contents | Published |
|---|---|---|
| `/tf_static` | Transforms between frames that never move relative to each other (e.g. a bolted-on sensor) | Once, because they don't change |
| `/tf` | Transforms between moving frames (wheels, odometry) | Continuously, at some frequency |

## Standard frames (mobile robots)

```
map ──▶ odom ──▶ base_footprint ──▶ base_link ──▶ sensors, wheels, ...
```

| Frame | Meaning | Published by |
|---|---|---|
| `map` | Fixed world frame. Doesn't drift. | Localisation (e.g. AMCL, SLAM) |
| `odom` | Where the robot *thinks* it started. Smooth, but drifts over time. | Odometry (wheel encoders, diff-drive controller) |
| `base_link` | The robot's body | `robot_state_publisher` (from the URDF) |

**Rule:** every frame has exactly **one parent**. TF is a tree, not a graph.

## Command line

```bash
ros2 run tf2_ros tf2_echo base_link laser_link       # live transform between two frames
ros2 run tf2_tools view_frames                       # PDF of the whole TF tree
```

Publish a static transform by hand (handy for testing):

```bash
ros2 run tf2_ros static_transform_publisher \
  --x 0.1 --y 0 --z 0.2 --roll 0 --pitch 0 --yaw 0 \
  --frame-id base_link --child-frame-id laser_link
```

## In code: look up a transform

```python
from tf2_ros import Buffer, TransformListener, TransformException

self.tf_buffer = Buffer()
self.tf_listener = TransformListener(self.tf_buffer, self)

try:
    # Pose of laser_link expressed in base_link, latest available
    t = self.tf_buffer.lookup_transform('base_link', 'laser_link', rclpy.time.Time())
except TransformException as e:
    self.get_logger().warn(f'No transform yet: {e}')
```

## Gotchas

- **Lookups fail right after start-up.** The buffer needs a moment to fill, so catch `TransformException` and try again later.
- **"Extrapolation into the future/past"** errors usually mean the clocks disagree. With Gazebo, check `use_sim_time` (see [19_simulation_time.md](19_simulation_time.md)).
- **Two publishers for the same frame** (e.g. Gazebo *and* a controller both publishing `odom → base_link`) makes the robot jump around in RViz.
